# PostgreSQL 切换与回退运行单（待演练批准）

本文件是操作顺序和放行条件，不是生产切换授权。当前生产仍使用 SQLite。
2026-09-20 已将正式代码 588ee36 合入兼容分支；最新代码与最新数据的完整复验仍待完成。

## 切换前必须具备的证据

- 固定正式代码提交、兼容分支提交和镜像摘要；后续正式代码变化需要重新评估。
- 最新一致性快照通过 integrity_check、foreign_key_check 和严格 schema 比对。
- 迁移后逐表行数与内容哈希、84 个外键及所有身份序列通过核验。数量必须以最新 schema 为准。
- 财务、薪资、结算、导出及附件内容与同一 SQLite 快照逐项对照；记录差异及处置结果。
- 最新代码的 SQLite 回归、PostgreSQL 集成、重复提交、桌面及手机操作验证通过。
- 备份在另一隔离库恢复成功；持续并发试验无错误、重复单据及金额差异。
- 核实后台任务、连接池、磁盘空间、权限、备份保留与告警；明确负责人和维护窗口。

现有 scripts/migrate_postgresql.py 只允许 *_rehearsal 数据库。正式切换前必须单独审查生产迁移入口及目标身份保护，不能通过把生产库命名为演练库绕过保护。

## 维护窗口执行顺序

1. 取得正式切换授权，记录开始时间、代码版本、负责人及回退判断时间。
2. 暂停所有写入入口：Web/API、照片处理、定时任务及其他写库进程；提示移动端暂停上传。确认在途请求完成，队列与重试任务不会继续写入。
3. 在写入冻结期间创建 SQLite 一致性备份，并同步附件、照片文件与校验清单。保留数据库、文件、配置和代码的配套版本，避免直接复制运行中的主库而遗漏 WAL。
4. 在非公开网络准备空 PostgreSQL 正式目标，迁移角色与运行角色分离；使用审查后的迁移入口。运行角色不得创建 schema 或改写迁移元数据。
5. 迁移完成但仍保持业务写入冻结。核验表内容、外键、序列、业务金额和附件清单；任何不一致均停止放行。
6. 在受控入口使用目标配置验证登录、关键查询、导出及预览。记录如需进行的合成写入及清理结果；禁止实际邮件或第三方业务操作。
7. 全部条件通过后才将正式应用指向 PostgreSQL，按顺序恢复写入和后台任务。核实只有一个正式写入数据源，禁止双写或旧进程继续写 SQLite。
8. 观察错误率、数据库锁等待、连接数、响应时间、照片队列和关键业务金额；留存验收记录及首份 PostgreSQL 备份。

演练中的亚秒级导入时间不等于维护窗口长度。须在最新完整数据和文件上计时，把冻结、备份、核验、启动和观察时间全部纳入。

## 回退边界

**放行业务写入前：** 停止目标应用和任务，恢复原 SQLite 配置、匹配的代码和文件集合；确认没有遗留 PostgreSQL 写入进程，再恢复业务。记录失败阶段并保留隔离目标用于分析。

**PostgreSQL 已接收新业务写入后：** 不得直接改回旧 SQLite。先重新冻结全部写入，备份 PostgreSQL 和新增附件，核对切换后的新增、修改、删除记录与审计轨迹。优先修复继续运行；确需回退时，必须制定并验证增量回灌和附件对账方案，明确确认不会丢失已接受的业务数据后才执行。

目前没有经过验证的 PostgreSQL → SQLite 自动增量回退工具，因此“随时改回连接地址”不是可用回退方案。
